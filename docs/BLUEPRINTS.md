The script's `BLUEPRINTS` block is the source of truth; this table mirrors it and adds deviations.

## Recipes

Coding rules every app follows (https://github.com/gadominas/app-blueprints/tree/main/recipes). They describe how the code is written, not a feature, so they aren't listed in the script's `BLUEPRINTS` block or in Built with.

| Recipe | Version | Since app version | Deviations |
| --- | --- | --- | --- |
| [safe-startup](https://github.com/gadominas/app-blueprints/blob/safe-startup-v1.1.0/recipes/safe-startup.md) | 1.1.0 | 1.16.0 | The digest loads a new page for every screen (boot, login, digest, refresh), as in its launch-screen deviation, so the recipe's single page with a placeholder becomes: an empty `#0E1116` window, then the boot page (runner and counter, with the launch screen) built inside it, then `bootApp`; the login, digest and error pages that follow are new pages loaded into the already visible window and count as booted (`window.__booted` is true on every page but the first). `__boot(st)` only marks the boot page booted and sets its status line: nothing is handed over in pieces (`window.__parts` stays empty), because the digest arrives as its own server-rendered page and `clientState()` doesn't exist. `__bootNote` writes into the boot page's `.boot` block (the app's placeholder) as well as `.booting`. `main()`, `bootApp` and `ev()` live in the digest's closure under "main flow" (the bridge, the Strava session and the feed are local to it); the lock helpers and `pause` sit above the entry point. The only data file is `sent-comments` (read in `loadData()`, guarded in `write()`); the AI settings and usage are local files read synchronously at load, as before (ai-configuration deviation), not iCloud. `settingsOk` is a `let` set in `loadSettings()`, which also skips its 1.9.x migration when `settings.json` couldn't be read. The deferred work at 0.7 s is the Strava session and feed (`boot()`), and it runs even when a data file is missing: the feed comes from Strava and nothing is saved over unread files. The update check (3.5 s) and the widget icon (6 s) moved out of `boot()` and the entry point. The Shortcuts `refresh` branch reads no data file, so it doesn't call `loadData()`. The start-up toasts (iCloud still delivering, or a damaged file kept aside and started fresh) are shown once the first digest is on screen (`icloudNote`, `repairNote`), because the boot page is replaced by it. Page code is ES5. The hidden details WebView was renamed `dv`/`dx` to free the name `ev` |
